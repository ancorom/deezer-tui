# Что прислать для ревью и переписывания Фаз 1–2 (deezer-tui)

Область проверки: **Фаза 1** (Cargo.toml, config, логгер, `dsp/cavacore.rs` + тесты) и
**Фаза 2** (`audio/decoder.rs`, `audio/output.rs`, rtrb-конвейер, интеграционный тест).
Всё, что относится к Фазам 3–5 (ui/, api/, stream.rs), пока не нужно — кроме заглушек модулей,
если они уже созданы и участвуют в компиляции.

## Блок A — обязательно, без этого ревью невозможно

| Файл | Зачем |
|---|---|
| `Cargo.toml` | версии, **features** (cpal `pipewire`, symphonia `mp3/aac/isomp4`), profile, edition/MSRV |
| `Cargo.lock` | единственное доказательство, какие версии реально собрались (cpal 0.18.2 / symphonia 0.6.1 / rtrb 0.4.1 / realfft 3.5) |
| `src/main.rs` | инициализация tracing, порядок запуска потоков, корректный shutdown |
| `src/config.rs` | чтение/запись `config.toml`, дефолты, обработка отсутствующего файла |
| `src/dsp/mod.rs` | публичный API модуля |
| `src/dsp/cavacore.rs` | ядро: окна Ханна, realfft, log-разметка, Monstercat, gravity, integral 0.77, autosens |
| `src/audio/mod.rs` | типы кольцевых буферов, общие структуры состояния |
| `src/audio/decoder.rs` | цикл пакетов symphonia 0.6, конвертация в f32, запись в 2 Producer |
| `src/audio/output.rs` | выбор `SampleRate(44100)`, RT-callback, атомарная громкость, underrun |
| **все остальные `.rs`, которые реально есть** | локалка часто плодит `ring.rs`, `state.rs`, `error.rs`, `utils.rs` — их нужно видеть |

Пришлите вместе с ними `tree.txt` (список файлов + число строк), чтобы я сразу увидел,
чего в списке не хватает. Скрипт `collect_audit.sh` делает это сам.

## Блок B — тесты и логи сборки (критично для «перепроверить»)

- `tests/**` (все интеграционные тесты), `benches/**`, `examples/**`, `build.rs` — если есть.
  Unit-тесты внутри `src/**` приезжают вместе с Блоком A.
- Вывод команд **как есть, включая warnings**, а не «всё зелёно»:
  ```
  cargo check --all-targets --message-format short   -> audit/check.log
  cargo test -- --nocapture                          -> audit/test.log
  cargo clippy --all-targets -- -D warnings          -> audit/clippy.log
  cargo tree -e normal,build --depth 1               -> audit/deps.txt
  rustc -Vv; cargo -V                                -> audit/toolchain.txt
  ```
- `rust-toolchain.toml`, `.cargo/config.toml` — если существуют.
- Хвост `deezer-tui.log` (последние ~300 строк) после реального прогона FLAC.
- Пример `config.toml` **с вычищенным `arl`** (`arl = "REDACTED"`).
- Что именно слышно на слух: играет / тишина / треск / ускоренное или замедленное
  воспроизведение / щелчки каждые N мс. Это мгновенно локализует баг
  (частота, интерливинг, размер чанка, underrun).

Из корня проекта:

```bash

```

Скрипт создаст `deezer-tui-audit.tar.gz` (обычно 100–400 КБ). Пришлите этот архив.
Если архивы неудобны — присылайте файлами в порядке: **A → B → C**, начиная с
`Cargo.toml` + `Cargo.lock` + `cavacore.rs` + `output.rs` + `decoder.rs`.

## Чек-лист: что я буду проверять (и где локалка обычно врёт)

**Фаза 2 — real-time safety и звук**
1. В cpal-callback нет `Mutex`/`RwLock`, аллокаций (`Vec::push`, `to_vec`, `Box`), `println!`,
   логов, `try_recv` на mpsc — только `rtrb::Consumer` и атомарная громкость.
2. `SampleRate(44100)` выбирается через `supported_output_configs()`, а не надеждой на
   `default_output_config()`; есть внятная стратегия, если устройство отказало (ресемплинг
   или явная ошибка, а не молчаливое ускорение звука на 8.8%).
3. Формат сэмплов устройства (`f32`/`i16`/`u16`) реально учтён, а не только `f32`.
4. rtrb 0.4 используется через chunk-API (`write_chunk`/`read_chunk`, `commit`) с обработкой
   **частичной** записи; нет бесконечного spin-loop, есть backpressure и сон вне callback.
5. Underrun заполняется нулями и считается (счётчик), а не паникует и не повторяет старый буфер.
6. Стерео-интерливинг L,R,L,R и моно-даунмикс `(L+R)*0.5` не перепутаны; ёмкости 65536 / 16384
   соблюдены; при переполнении VisRingBuffer старые сэмплы дропаются, а не блокируют декодер.
7. Symphonia 0.6: корректный `probe`/`MediaSource`, цикл `next_packet`, обработка `EndOfStream`,
   `ResetRequired`, `Seek`; конвертация S16/S24/S32 → f32 с правильным делителем, а не `as f32`.
8. Громкость: `AtomicU32` + `f32::from_bits`, `Ordering::Relaxed`, без_denormals/клиппинг,
   плавность (без щелчков при изменении).
9. Декодер не крутится на 100% CPU и не умирает молча; ошибки уходят в лог/канал, потоки
   корректно завершаются при выходе.

**Фаза 1 — DSP**
10. Тишина даёт ровно нули (нет DC-offset, нет «шума» от нормировки FFT).
11. Окно Ханна, размер окон 4096/2048, перекрытие и планировщик `realfft` (план
    переиспользуется, а не создаётся каждый кадр — иначе 60 FPS не будет).
12. Нормировка амплитуд FFT, перевод в dB/масштаб, частотная эквализация.
13. Log-разметка 50–10000 Гц: границы бинов не вырождаются в один бин на низах
    (классический баг: `bin[i] == bin[i+1]` при N=2048 и 60 столбиках).
14. Monstercat-сглаживание, квадратичная gravity со сбросом `fall_step` на новом пике,
    интегральный фильтр 0.77, autosens 0.985 / 1.001 — точные коэффициенты и порядок применения.
15. Тесты **assert-ят поведение** (100 Гц → низы, 5000 Гц → верхи, плавный спад за N кадров),
    а не просто «не паникует»; нет подгонки порогов под неверную реализацию.

**Общее**
16. Нет `.unwrap()`/`expect()` на файловых/сетевых операциях, `anyhow::Result` по всей цепочке.
17. Логгер файловый (`tracing-appender`), не пишет в stdout, не ломает будущий TUI.
18. Конфиг: атомарная запись, дефолты, `DEEZER_ARL` из env, права на файл с токеном.
19. `cargo clippy --all-targets -- -D warnings` действительно чистый (включая тесты).
