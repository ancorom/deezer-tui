# PLAN.md — План разработки и критерии приёмки (Редакция: Ноябрь 2026)

## Этап 1: Математическое ядро Cavacore и DSP-конвейер
Цель: Получить полностью протестированный модуль спектроанализатора на чистом Rust без привязки к аудиокарте и сети.
- Задачи:
  1. Настроить файловый логгер tracing и конфигурацию в src/config.rs.
  2. Портировать алгоритм из docs/reference/cava/cavacore.c в src/dsp/cavacore.rs с использованием realfft 3.5.
- Критерии валидации (Unit-тесты по аналогии с cavacore_test.c):
  - Подача буфера из нулей (0.0f32) выдаёт нулевые высоты столбиков.
  - Подача чистой синусоиды 100 Гц активирует нижние (басовые) столбики, а синусоиды 5000 Гц — верхние столбики спектра.
  - При резком прекращении сигнала столбики опускаются плавно за несколько вызовов process() благодаря фильтру гравитации и интегральному сглаживанию.

## Этап 2: Локальный аудиодвижок (Symphonia 0.6 + CPAL 0.18 + rtrb 0.4)
Цель: Проиграть локальный .flac-файл через cpal 0.18 (PipeWire/ALSA) с точным соблюдением частоты 44.1 кГц и передать аудиопоток в Cavacore без мьютексов.
- Задачи:
  1. Реализовать src/audio/decoder.rs (чтение медиапотока через symphonia 0.6, декодирование FLAC в f32 и запись в два буфера rtrb 0.4).
  2. Реализовать src/audio/output.rs (явный выбор SampleRate(44100) в cpal 0.18, real-time чтение из AudioRingBuffer с атомарной регулировкой громкости).
- Критерии валидации:
  - Тестовое воспроизведение сгенерированного аудио-буфера в памяти корректно наполняет оба кольцевых буфера rtrb без паник и блокировок.

## Этап 4: Криптография Blowfish, кэширующий DeezerStream и сетевой клиент
Цель: Заменить локальный файл на прямое потоковое воспроизведение FLAC из Deezer по токену ARL с поддержкой перемотки (Seek) и префетча за 20 секунд до конца трека.
- Задачи:
  1. Реализовать src/api/crypto.rs (генерация 16-байтного ключа через MD5 и XOR с секретом g4el58wc0zvf9na1, расшифровка блока 2048 байт алгоритмом Blowfish-CBC).
  2. Написать src/api/client.rs (на базе reqwest 0.13: авторизация в gw-light.php, получение sid, api_token, license_token и URL потока через [media.deezer.com/v1/get_url](https://media.deezer.com/v1/get_url)).
  3. Создать src/audio/stream.rs (DeezerStream с реализацией Read + Seek + MediaSource, расшифровывающий каждый блок i % 3 == 0 и сохраняющий расшифрованные чанки во временный буфер/файл tempfile).
- Критерии валидации:
  - Unit-тест шифрует тестовый буфер из 8192 байт (4 чанка по 2048 байт, где чанки 0 и 3 зашифрованы Blowfish-CBC) и проверяет, что DeezerStream при чтении произвольными кусками со смещением Seek возвращает байт-в-байт исходный массив.

  3. Реализовать загрузку бесконечной очереди Deezer Flow (radio.getUserRadio) и синхронизированных текстов песен (song.getLyrics) с подсветкой активной строки по таймкоду (src/ui/views/flow_lyrics.rs).

- Критерии валидации:
